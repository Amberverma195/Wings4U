### 3.3 Keyboard Focus Remediation Code

Create a customer-facing focus trap and modal hook modeled after the admin implementation:

```tsx
// apps/web/src/hooks/use-modal-dialog.ts
"use client";

import { useEffect, useRef, type RefObject } from "react";

export function useModalDialog({
  dialogRef,
  initialFocusRef,
  onClose,
  active = true,
}: {
  dialogRef: RefObject<HTMLElement | null>;
  initialFocusRef?: RefObject<HTMLElement | null>;
  onClose: () => void;
  active?: boolean;
}) {
  const onCloseRef = useRef(onClose);
  useEffect(() => { onCloseRef.current = onClose; }, [onClose]);

  useEffect(() => {
    if (!active) return;
    const dialog = dialogRef.current;
    if (!dialog) return;

    const previousFocus = document.activeElement instanceof HTMLElement ? document.activeElement : null;
    const previousOverflow = document.body.style.overflow;
    document.body.style.overflow = "hidden";

    (initialFocusRef?.current ?? dialog).focus();

    const getFocusable = () =>
      Array.from(
        dialog.querySelectorAll<HTMLElement>(
          'a[href], button:not([disabled]), input:not([disabled]):not([type="hidden"]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])'
        )
      ).filter(el => !el.closest('[aria-hidden="true"]') && el.getClientRects().length > 0);

    const onKeyDown = (event: KeyboardEvent) => {
      if (event.key === "Escape") {
        event.preventDefault();
        event.stopPropagation();
        onCloseRef.current();
      } else if (event.key === "Tab") {
        const elements = getFocusable();
        if (elements.length === 0) {
          event.preventDefault();
          dialog.focus();
          return;
        }
        const first = elements[0];
        const last = elements[elements.length - 1];

        if (event.shiftKey && document.activeElement === first) {
          event.preventDefault();
          last.focus();
        } else if (!event.shiftKey && document.activeElement === last) {
          event.preventDefault();
          first.focus();
        }
      }
    };

    const onFocusIn = (event: FocusEvent) => {
      if (!dialog.contains(event.target as Node)) {
        const elements = getFocusable();
        (elements[0] ?? dialog).focus();
      }
    };

    document.addEventListener("keydown", onKeyDown, true);
    document.addEventListener("focusin", onFocusIn);

    return () => {
      document.removeEventListener("keydown", onKeyDown, true);
      document.removeEventListener("focusin", onFocusIn);
      document.body.style.overflow = previousOverflow;
      if (previousFocus?.isConnected) previousFocus.focus();
    };
  }, [dialogRef, initialFocusRef, active]);
}
```

### 4.1 Issue Description & WCAG Compliance
In [`apps/web/src/components/customer-auth.tsx`](file:///d:/Projects/Websites/Wings4U/Code/apps/web/src/components/customer-auth.tsx), several customer authentication and registration fields rendered visual text labels (such as "Full name", "Phone number", "Email", "Password", and "Confirm password"), but these labels were not programmatically associated with their corresponding `<input>` elements.

- **WCAG 2.1 Criteria 1.3.1 Info and Relationships (Level A):** Information, structure, and relationships conveyed through presentation must be programmatically determinable or available in text.

### 5.5 Privacy Compliance & Statutory Framework Alignment

1. **PIPEDA (Personal Information Protection and Electronic Documents Act - Canada):**
   - **Principle of Minimization:** Customer data collected is strictly limited to information necessary for order fulfillment, account authentication, and delivery calculation.
   - **Right to Erasure / Rectification:** Complies via the comprehensive customer account deletion protocol (`Docs/account-deletion.md`), which irreversibly strips customer PII and anonymizes financial records.
   - **No Marketing Resale:** Personal information is never rented, traded, or sold to data brokers or advertising networks.

2. **CASL (Canada’s Anti-Spam Legislation):**
   - Commercial electronic messages sent via Resend are transactional in nature (order receipts, security verification codes, loyalty balance updates linked to customer transactions).

### 6.1 Testing Methodology & Assisted Technology Environment

Screen reader testing was performed across both the **Web Application (`apps/web`)** and the **Mobile Native Application (`apps/application`)**, simulating the complete customer purchasing lifecycle from initial storefront discovery to post-order fulfillment.

#### Tested Assistive Technologies:
- **Windows Narrator (Windows 11):** Tested keyboard cursor navigation, form mode, and live region announcements.
- **NVDA (NonVisual Desktop Access v2024.4):** Tested browse mode (virtual cursor), button list navigation (`B` key), and landmark jumps (`D` key).
- **iPhone VoiceOver (iOS 18):** Tested touch exploration, swipe right/left traversal, rotor actions, and two-finger "Z" escape scrub gestures.
- **Android TalkBack (Android 14/15):** Tested linear touch focus, granularity navigation, double-tap activation, and accessibility state announcements (`selected`, `disabled`, `checked`).

#### Key Accessibility Criteria Tested:
- **WCAG 2.1 Criteria 4.1.2 (Name, Role, Value - Level A):** Every interactive control must expose a programmatically determinable name, role, and current state (e.g. `pressed`, `checked`, `expanded`, `disabled`).
- **WCAG 2.1 Criteria 2.4.4 (Link Purpose in Context - Level A):** Every button and action must have an unambiguous purpose, avoiding repeated generic labels like "Button", "Edit", or "Remove" without item context.
- **WCAG 2.1 Criteria 1.3.1 (Info and Relationships - Level A):** Grouped controls (such as pickup vs delivery, tip percentages, and payment preferences) must expose their group relationship (`role="radiogroup"`, `role="tablist"`).
- **WCAG 2.1 Criteria 3.3.2 (Labels or Instructions - Level A):** Stepper controls (+ / -) must inform the user what item is being adjusted and what the resulting quantity will be.
